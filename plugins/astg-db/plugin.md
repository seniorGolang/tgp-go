# Плагин astg-db — модель из локальной базы контрактов

## Назначение

Pre-плагин: подставляет в пайплайн уже сохранённую **модель проекта** из локальной базы контрактов, чтобы генерировать server/clients/swagger/kafka **без повторного разбора** исходников. Базу заполняет `astg-hook`.

Срабатывает только если в запросе **ещё нет** `project` и передана опция `from-db`. Иначе плагин ничего не делает.

## Когда использовать

- Генерация по зафиксированной версии контрактов (CI, другой репозиторий без `contracts/`).
- Воспроизведение старой ветки/тега после сохранения через hook.
- Интерактивный выбор проекта/версии при локальной отладке.
- Инспекция сохранённой модели: `tg astg json --from-db …` (см. `astg-json`).

Не используйте для правки контрактов: редактируйте исходники и сохраняйте новый снимок через hook.

## Опции пайплайна

| Опция | Тип | Описание |
| ----- | --- | -------- |
| `from-db` | строка | Ref на проект в БД (см. ниже) или **пустая строка** — интерактивный выбор проекта/версии. |
| `all-contracts` | bool | Не предлагать интерактивный выбор контрактов; оставить полную загруженную модель. На команде `tg astg json` по умолчанию `true`. |

Если `from-db` не передан — плагин пропускается. Если `project` уже есть — тоже.

## Формат ссылки (ref)

| Ref | Смысл |
| --- | ----- |
| `` (пустое `--from-db`) | Интерактивный выбор проекта (и при необходимости контрактов) |
| `ключ` / `ключ@версия` | Проект; без версии — **последняя** запись по дате обновления в индексе |
| `ключ:Контракт1,Контракт2@версия` | Фильтр контрактов уже в ref; UI выбора контрактов не показывается |
| `ключ@версия:Контракт1,Контракт2` | Эквивалентная форма фильтра |

Примеры: `myapi@v1.0.1`, `github.com.acme.api@main`, `github.com.acme.api:UserService,OrderService@v1.2.0`.

**Ключ проекта** — не «короткое имя модуля из головы», а нормализованный идентификатор, который записал `astg-hook`: обычно sanitized remote Git URL (`github.com.org.repo` вместо `https://github.com/org/repo.git`), иначе module path (слэши → точки; односегментные ключи могут получить префикс `local.`). Если ref «не находится», сначала посмотрите интерактивный список или экспорт с `--from-db` без версии.

Список контрактов **в ref** сразу фильтрует загруженную модель (связанные `services` тоже; карта `types` **не** урезается).

## Интерактивный выбор и `--contracts`

| Ввод | Выбор проекта | Выбор контрактов в DB |
| ---- | ------------- | --------------------- |
| `--from-db` (пусто) | да | да, если нет `all-contracts` и нет списка в ref / `--contracts` |
| `--from-db project@version` | нет | да (те же условия) |
| `--from-db project:C1,C2@version` | нет | нет — фильтр уже в ref |
| `--from-db project@version --contracts C1,C2` | нет | нет — UI выбора **отключён** |
| `--from-db …` + `all-contracts=true` | по ref | нет — полная модель из БД |

Важно разделить три слоя:

1. **Фильтр модели из БД** делает только список контрактов **в ref** (`FilterProject`).
2. **`--contracts`** на генераторе (server, clients, …) для `astg-db` лишь **подавляет** интерактивный UI; сам `astg-db` при `--contracts` **не** урезает загруженную модель.
3. **Урезание для генерации** выполняет уже command-плагин на своей копии модели.

Пустая база или отмена интерактивного выбора — ошибка.

## Что получается / как работает для пользователя

1. Пайплайн видит `from-db` и отсутствие `project`.
2. `astg-db` резолвит ref (или спрашивает), читает снимок, при необходимости фильтрует по контрактам **из ref**.
3. В запрос кладётся `project` — дальше генераторы работают как с локальным разбором.
4. `astg-hook` в том же запуске **не** перезаписывает БД (skip при `from-db`).

Перед генерацией в CI полезно явно выгрузить ту же ref:

```bash
tg astg json --from-db name@version -o .tg/db.json
```

## На что обратить внимание

- Bare `name` без `@версия` = «latest» в индексе — **не** стабильный pin для релизов.
- Путаница `--contracts` vs контракты в ref: первое не фильтрует DB-модель; второе — фильтрует.
- После фильтра в ref типы остаются полным графом снимка — «лишние» typeID в JSON нормальны.
- Неизвестный ключ: сверьте, как hook нормализовал remote/module; короткий `myapi` сработает только если так записали в индекс.
- Если генерация всё равно идёт по локальным исходникам — в запросе уже был `project` или `from-db` не дошёл до пайплайна.

## Ограничения

- Нужна ранее сохранённая база (`astg-hook`); пустой индекс — ошибка.
- Плагин не редактирует и не валидирует аннотации — только загружает снимок.
- Hand-edit файлов БД / индекса не поддерживается.

## Связь с другими плагинами

Зависит от `astg` в пайплайне. Писатель БД — `astg-hook`. Инспекция — `astg-json` / `tg astg json --from-db`. Документация: `tg plugin doc astg-hook`, `tg plugin doc astg-json`.
