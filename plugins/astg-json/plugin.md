# Плагин astg-json — экспорт resolved-модели в JSON

## Назначение

Command-плагин: выводит полную resolved-модель проекта (контракты, методы, типы, аннотации, provenance) в JSON — в stdout или в файл. Это основной способ **инспектировать** то, что видят генераторы, без генерации кода.

Команда: `tg astg json`.

## Когда использовать

- Понять, какие контракты/методы/аннотации реально попали в модель после разбора.
- Отладить «почему генератор сделал не то»: смотреть resolved types, mapping, errors — а не гадать по `contracts/`.
- Сравнить local vs DB перед regenerate (`-o` два файла, затем diff/`jq`).
- Выгрузить сохранённую версию из локальной БД (`--from-db`, нужен `astg-db`).

Не используйте для правки контрактов и не подменяйте генерацию ручным редактированием JSON.

## Команда и параметры

```bash
# Текущий проект (./contracts) → stdout
tg astg json

# → файл (предпочтительно для инспекции)
tg astg json -o .tg/project.json

# Версия из локальной БД
tg astg json --from-db myapi@v1.0.1 -o .tg/db.json
tg astg json --from-db myapi
tg astg json --from-db
```

| Опция | Описание |
| ----- | -------- |
| `out` (`-o`) | Файл вывода; без флага — stdout. |
| `contracts-dir` | Папка контрактов для локального разбора (по умолчанию `contracts`). |
| `all-contracts` | Полная модель из БД без интерактивного выбора контрактов (**по умолчанию `true`**). |

Опция `from-db` появляется, если в пакете подключён **astg-db**. Формат ref — `tg plugin doc astg-db`.

## Что получается / как работает для пользователя

- **Без `from-db`:** модель строит `astg` (исходники или кэш) → JSON.
- **С `from-db`:** модель даёт `astg-db`; при default `all-contracts=true` интерактивный выбор контрактов не предлагается — в файл попадает полный сохранённый снимок (или уже отфильтрованный ref, если контракты перечислены в самой ссылке).

JSON отражает аннотации **на исходных уровнях** (пакет / контракт / метод / поле). Inherited-значения генераторы вычисляют cascade’ом сами — в экспорте они физически не продублированы на каждый метод.

Типичный цикл отладки генератора:

1. `tg astg json -o .tg/project.json`
2. Точечные запросы через `jq` (имена контрактов, ключи annotations, typeID).
3. Правка `contracts/` / `contracts/dto`.
4. Повторный экспорт и regenerate.

## На что обратить внимание

- **Пишите в файл (`-o`)**, а не сбрасывайте весь JSON в чат/лог: модель большая; в контекст агента кладите только нужные фрагменты после `jq`.
- `all-contracts` по умолчанию `true` — для `astg json` это ожидаемо; на других командах с `from-db` поведение UI выбора может отличаться.
- `--from-db` без версии = latest в индексе, не pin релиза.
- Флаг-аннотации часто сериализуются как JSON `true` (пустой value в DocTags): наличие ключа = включено.
- JSON **не** мержит inherited-аннотации на каждый метод — cascade считайте сами (или смотрите skill `tgp-astg-json`).
- Сравнение local vs DB: два файла (`-o`) и diff/`jq`, а не визуальный просмотр stdout.

## Ограничения

- Нужен `astg`. Для `--from-db` — ещё `astg-db`.
- Плагин только экспортирует; не сохраняет в БД (это `astg-hook`) и не генерирует код.
- Не заменяет `tg plugin doc astg`: каталог аннотаций живёт там, здесь — снимок конкретного проекта.

## Связь с другими плагинами

Читает модель от `astg` или `astg-db`. Каталог аннотаций — `tg plugin doc astg`. Для агентов: skill `tgp-astg-json` (`tg pkg skills install`).
